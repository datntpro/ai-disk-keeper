# Localization workflow

`Sources/AIDiskKeeperUI/Resources/Localizable.xcstrings` is a **derived file**. It is committed (builds and tests need it) but never edited by hand:

- English comes from the `loc("stable.key", "English")` calls in code.
- Vietnamese comes from `scripts/l10n/<Txx>.vi.py` (`VI = {key: text}`; `WHY = {...}` for `protected.why.*` keys).

The file is marked `linguist-generated` / `-diff` in `.gitattributes`, so reviewers see a collapsed diff.

## Per PR

1. Add exactly one `scripts/l10n/<Txx>.vi.py` and use your own key prefix. A file may declare `PREFIXES = ("apps.",)`; CI rejects keys outside it (planned tasks have defaults in `scripts/l10n-apply.py`).
2. Run `scripts/l10n-regen.sh <Txx>` whenever the catalog needs updating. It takes the catalog from `origin/main` (`--base REF` to change), runs `l10n-extract.py --sync`, applies only your vi file, then runs `--check`. Needs Xcode (not Command Line Tools) selected.
3. Commit the result as `[Txx] Resync string catalog`.

Never resolve a catalog conflict by hand and never rebase only because of one: at merge time, `git rebase origin/main`, and if the catalog is the only conflict run `scripts/l10n-regen.sh <Txx>`, `git add` it and `git rebase --continue`.

## Tools

| Command | What it does |
|---|---|
| `scripts/l10n-regen.sh [--base REF] <Txx>…` | Rebuild the catalog for a PR (above). |
| `scripts/l10n-regen.sh --verify` | CI, no build: every vi-file key exists in the catalog with the same vi text, no key in two vi files, prefixes respected. |
| `python3 -I scripts/l10n-apply.py <file.py>…` | Apply vi files. Idempotent: a key already equal with state `translated`/`needs_review` is untouched, so reviewed strings are never reset. Exits 1 on an unknown key. |
| `python3 -I scripts/l10n-extract.py --check\|--sync\|--dump` | Catalog vs. code lint / sync / key dump. |

## Plurals

A key whose English default interpolates an `Int` (`loc("x.items", "\(n) items")`, format `%lld`) must be a String Catalog plural entry. Declare it in your vi file next to `VI`:

```python
PLURALS = {
    "x.items": {"en": {"one": "%lld item", "other": "%lld items"}, "vi": {"other": "%lld mục"}},
}
```

`l10n-apply.py` writes both languages as `variations.plural` (Vietnamese has only `other`), `--check` requires the English `other` to equal the code default, and `--verify` compares both. Never join a count and a noun by hand ("1 items").
